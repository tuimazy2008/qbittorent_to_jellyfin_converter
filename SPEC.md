# jellyprep — спецификация v0.1 (2026-11-20)

Сервис берёт завершённые торренты из qBittorrent, распознаёт, что это
(фильм/сериал/сезон/серия), при необходимости перекодирует видео и добавляет
дорожку с выровненным звуком, раскладывает результат в библиотеку Jellyfin и
удаляет оригинал из qBittorrent после выполнения условий раздачи.

Рабочее название `jellyprep`, можно поменять до первой публикации.

## Принятые решения

| # | Тема | Решение |
|---|---|---|
| 1 | Где перекодировать | На сервере (Intel QSV/VAAPI), ночная очередь. LLM на отдельной машине с GPU. |
| 2 | Распознавание | guessit + поиск в TMDB. Если однозначно, обрабатывается сразу. Сложные случаи → LLM. В LLM уходят только дерево имён файлов и вывод ffprobe. LLM **необязательна**: если она настроена, но недоступна, задача ждёт в очереди (с кнопкой «распознать вручную»). Если не настроена, задача сразу идёт на ручное подтверждение. |
| 3 | Что обрабатывать | Только включённые в интерфейсе категории qBittorrent. |
| 4 | Подтверждение | Настраивается по категории: `auto` / `auto_if_confident` / `always_confirm`. |
| 5 | Куда класть | Новая папка-библиотека, своя подпапка на каждую категорию (соответствие категория → папка задаётся в интерфейсе). |
| 6 | Метаданные | Имена по конвенции Jellyfin + `[tmdbid-N]` в имени папки. `.nfo` только если в TMDB ничего не нашлось. |
| 7 | Видео | H.264 High 8-bit yuv420p (играет везде). Перекодировать, если высота > 1080 **или** битрейт > порога **или** кодек не из списка разрешённых. Все пороги настраиваются. HDR → SDR с tone mapping (иначе картинка блёклая). Иначе только remux без перекодирования. |
| 8 | Звук | Оригинальные дорожки остаются. Добавляется новая дорожка «Голос громче»: стерео, центр усилен, сжатие динамики + нормализация громкости. Она ставится дорожкой по умолчанию. |
| 9 | Дорожки/субтитры | Оставлять только выбранные языки (по умолчанию rus, eng), остальные удалять. |
| 10 | Удаление оригинала | После того, как результат проверен **и** (рейтинг ≥ N **или** срок раздачи ≥ M дней). N, M задаются по категории. |
| 11 | Место на диске | Защита: задача не стартует, если после неё свободно меньше X ГБ. |
| 12 | Распространение | Открытый код на GitHub + Docker-образ. Никаких путей и адресов в коде, всё задаётся настройками. |
| 13 | Стек | Python 3.12, FastAPI, SQLite, ffmpeg, простой веб-фронтенд. |
| 14 | Существующие файлы | Есть режим «обработать папку»: те же шаги для файлов, у которых нет торрента. Шаг cleanup для них не выполняется, исходник удаляется только по явному выбору. |
| 15 | Доступ | Только LAN. Без авторизации в v1, порт публикуется на LAN-адрес. |
| 16 | Ключи и пароли | Вводятся только через интерфейс, хранятся в `/config`, в логах и API наружу не отдаются. |
| 17 | Первый запуск | Пошаговый мастер с подробным описанием каждой опции и выбором из вариантов (см. ниже). |

## Архитектура

Один контейнер, внутри: веб-интерфейс + API, планировщик, воркер очереди.

```
qBittorrent API ──► watcher ──► probe (ffprobe) ──► identify ──► plan ──► [approve] ──► execute ──► verify ──► Jellyfin refresh
                                                     │  guessit+TMDB                 │ remux/hardlink: сразу
                                                     └─► LLM (если неуверенно)       └ transcode: в ночное окно
                                                                                                     │
                                                                          cleanup (ratio/время) ◄────┘
```

### Внешние зависимости (всё настраивается)
- **qBittorrent WebUI API**: URL, логин/пароль (или без авторизации). Действия: список торрентов, удаление торрента с файлами.
- **TMDB API**: ключ пользователя (бесплатный).
- **LLM**: OpenAI-совместимый endpoint или Ollama API (URL + модель). Проверка доступности перед каждой задачей.
- **Jellyfin API** (опционально): ключ, обновление библиотеки после раскладки.
- **Пути**: соответствие «путь в qBittorrent → путь в контейнере» (например `/media` → `/media`).

### Тома контейнера
- `/config`: SQLite, настройки, логи.
- Медиа-том: тот же, что у qBittorrent, чтобы работали хардлинки (исходник и библиотека должны быть на одной ФС).
- `/dev/dri`: аппаратное кодирование.

## Конвейер

1. **watcher**: раз в N минут берёт завершённые торренты из включённых категорий, которых ещё нет в БД.
2. **probe**: ffprobe каждого видеофайла: кодек, разрешение, битрейт, HDR, дорожки, языки, длительность.
3. **identify**
   - guessit по имени файла и папки → кандидат (тип, название, год, сезон, серия).
   - Поиск в TMDB → оценка уверенности (совпало ли название, год, количество серий в сезоне).
   - Если уверенность ниже порога, или структура неясна (`Season 01` без названия, сборник, кириллица/транслит, «01.серия»), запрос в LLM: дерево файлов + ffprobe → JSON по схеме. Затем повторная проверка через TMDB.
4. **plan**: для каждого файла: путь в библиотеке, действие (`hardlink` / `remux` / `transcode`), какие дорожки оставить, нужна ли дорожка «Голос громче». Мусор (сэмплы, .txt, .url, картинки торрента) пропускается.
5. **approve**: по режиму категории. В интерфейсе видно: «Распознал как X (TMDB 1234), 10 серий, перекодирую 1080p, добавлю голосовую дорожку». Можно поправить распознавание вручную.
6. **execute**
   - Сначала пишется во временный файл `*.partial` в той же папке библиотеки, по готовности переименовывается.
   - `hardlink`, только если файл не меняется вообще (дорожки/звук не трогаем). Тогда удаление торрента места **не** освободит, и в интерфейсе это показано.
   - `remux`, `transcode` создают новый файл.
   - Перекодирование только в ночное окно (настраивается), по одной задаче за раз.
7. **verify**: ffprobe результата, длительность совпадает (±1 с), нужные дорожки есть.
8. **refresh**: обновление библиотеки Jellyfin.
9. **cleanup**: периодически. Если verify успешен и выполнено условие раздачи, торрент удаляется вместе с файлами через API qBittorrent.

## Видео: правила по умолчанию (все в интерфейсе)
- Перекодировать, если: высота > 1080; битрейт видео > 12 Мбит/с; кодек не в `[h264]` (HEVC, MPEG-4 ASP/XviD, VC-1, MPEG-2 тоже перекодируются, потому что играют не везде).
- Цель: H.264 High@4.1, ≤1920×1080 с сохранением пропорций, 8-bit, качество QSV ICQ ~23 (ориентир 6–10 Мбит/с для 1080p).
- HDR10/HLG → SDR BT.709 (tone mapping через `vpp_qsv`, запасной вариант на CPU: `zscale`+`tonemap`).
- Чересстрочное (`.ts` 1080i) → деинтерлейс.
- Контейнер: MKV.

## Звук: дорожка «Голос громче»
- Источник: дорожка выбранного языка (приоритет задаётся, по умолчанию rus → eng).
- 5.1/7.1 → стерео с усиленным центром, затем `dynaudnorm` (сжатие тихое/громкое) и `loudnorm` (целевая громкость, по умолчанию −16 LUFS).
- Кодек AAC 192 кбит/с стерео. Флаг default, оригиналы без флага default.
- Параметры (усиление центра, сила сжатия, целевая громкость) задаются профилем в интерфейсе.

## Мастер первого запуска
Пока настройка не завершена, вместо интерфейса открывается мастер. Как устроен каждый шаг:
- что это за опция и зачем она нужна, простыми словами;
- варианты карточками: у каждого описание плюсов и минусов, один помечен «Рекомендуется»;
- «Дополнительно» раскрывает точные числа для тех, кому нужно;
- кнопка «Проверить» везде, где есть подключение (qBittorrent, TMDB, LLM, Jellyfin, видеокарта);
- можно вернуться назад, а потом перезапустить мастер из настроек.

Шаги:
1. **Язык интерфейса**: русский / English.
2. **qBittorrent**: адрес, логин/пароль или «без пароля». Проверка, затем автоопределение путей: мастер берёт пути сохранения из qBittorrent и проверяет, что они видны в контейнере. Если нет, предлагает соответствие путей.
3. **Категории**: список берётся из qBittorrent. Для каждой: обрабатывать или нет; тип (фильмы / сериалы / определять автоматически); папка библиотеки (предлагается `library/<категория>`); режим подтверждения. Категории Radarr/Sonarr помечены «уже обрабатываются Radarr/Sonarr, рекомендуем выключить».
4. **TMDB**: зачем он нужен, как получить ключ (пошагово со ссылкой), поле ключа, проверка.
5. **Локальная модель (необязательно, можно пропустить)**: «не использовать» (по умолчанию) / Ollama / OpenAI-совместимый сервер. Адрес, список моделей берётся с сервера, проверка тестовым запросом. Подсказка про `OLLAMA_HOST=0.0.0.0`. Описание: без модели всё работает. Однозначные случаи обрабатываются через TMDB, а сложные попадают на ручное подтверждение, где название/сезон указываются в интерфейсе. Модель можно подключить позже в настройках.
6. **Видео**: готовые профили:
   - «Максимальная совместимость» (рекомендуется): H.264 1080p, перекодировать всё, что больше 1080p, выше 12 Мбит/с или не H.264;
   - «Баланс»: H.264, перекодировать только больше 1080p и HDR;
   - «Не трогать видео»: только remux.
   Дополнительно: пороги, качество, tone mapping, деинтерлейс. Проверка видеокарты: какие кодеки доступны аппаратно.
7. **Звук**: добавлять ли дорожку «Голос громче»; сила обработки: «лёгкая / средняя (рекомендуется) / сильная (ночной режим)», с описанием, как это звучит. Какой язык брать для этой дорожки.
8. **Языки дорожек и субтитров**: какие оставить (по умолчанию rus, eng), что делать, если нужного языка нет (оставить всё / оставить первую дорожку).
9. **Удаление из qBittorrent**: профили «Раздать 2× или 30 дней (рекомендуется)», «Раздать 1× или 14 дней», «Никогда не удалять», «Своё». Объясняется, что при хардлинке удаление место не освобождает.
10. **Расписание и место**: ночное окно для перекодирования (по умолчанию 01:00–08:00), минимум свободного места (по умолчанию 50 ГБ).
11. **Jellyfin** (можно пропустить): адрес, API-ключ, проверка. Подсказка, какие библиотеки создать и с каким типом.
12. **Итог**: сводка выбранного. Старт в режиме dry-run (рекомендуется): сервис только показывает, что сделал бы, и ничего не меняет на диске.

## Интерфейс
- **Очередь**: задачи, этап, прогресс ffmpeg, ETA, ошибки, кнопки повторить/отменить.
- **Торренты**: распознавание, план, подтверждение/правка, статус раздачи и сколько осталось до удаления.
- **Категории**: включена/выключена, папка библиотеки, тип (фильмы/сериалы/авто), режим подтверждения, правила удаления, профили видео/звука.
- **Профили**: видео (пороги, качество), звук (параметры голосовой дорожки), языки.
- **Настройки**: qBittorrent, TMDB, LLM, Jellyfin, пути, ночное окно, защита диска, dry-run.
- **Журнал**.
- Язык интерфейса: ru/en.

## Этапы
1. ✅ **MVP** (v0.1, 2026-11-20): каркас, БД, мастер первого запуска, подключение к qBittorrent, guessit+TMDB, план, hardlink/remux в библиотеку, интерфейс категорий и подтверждений, удаление по рейтингу/времени, режим dry-run.
2. ✅ **Медиа** (v0.2, 2026-11-20): перекодирование через QSV, tone mapping, голосовая дорожка, фильтр языков, ночное окно, защита диска.
3. **LLM (опционально)**: запасное распознавание, ожидание доступности модели. До этого этапа сложные случаи решаются ручным подтверждением.
4. **Публикация**: Dockerfile, docker-compose пример, GitHub Actions → образ в GHCR, README (en), лицензия.

## Состояние v0.1
- Готово: мастер первого запуска (9 шагов, у каждой опции описание и вариант «Рекомендуется», кнопки «Проверить»), синхронизация с qBittorrent, распознавание guessit + свои правила для русских релизов + TMDB, ручная правка на странице торрента, раскладка хардлинками, удаление оригинала по рейтингу/сроку после проверки, dry-run, обновление Jellyfin, защита от cross-site POST. 47 тестов.
- Перепаковка в MKV есть, но по умолчанию выключена: она делает полную копию файла и места не экономит (Jellyfin и так играет AVI/TS). Решение «перекодировать или нет» относится к этапу 2.
- Интерфейс пока только на русском, английский добавится на этапе публикации.
- Проверено на списке файлов реальных раздач тестового сервера: большинство раскладывается правильно. «Тайны следствия» (номер дела + «(N сер.)») уходят на ручную проверку, это кандидат для LLM.

## Состояние v0.2
- Перекодирование: VAAPI (Intel/AMD) с запасным вариантом на процессоре (libx264). SDR полностью на видеокарте; HDR: декодирование и уменьшение на видеокарте, tone mapping (zscale + hable) на процессоре в несколько потоков, кодирование на видеокарте. Аппаратный tone mapping Intel (`tonemap_vaapi`) на Kaby Lake даёт слишком тёмную картинку, а libplacebo/Vulkan на ней не работает (зелёный кадр, падения), поэтому оба не используются.
- Замеры на тестовом сервере (i7-7500U, Intel HD 620): 1080p BluRay → 1080p, все дорожки + «Голос громче» — ~2× реального времени; 4K HDR → 1080p — ~0.55× (двухчасовой фильм ≈3.6 ч).
- «Голос громче»: стерео AAC 192k, центр усилен, `dynaudnorm` + `loudnorm` −16 LUFS, дорожка по умолчанию, оригиналы остаются.
- Фильтр языков звука и субтитров; лимит дорожек на язык (по умолчанию без лимита).
- Тяжёлые задачи идут в отдельном потоке по одной; перекодирование ждёт ночного окна, кнопка «Выполнить сейчас».
- «Перенос»: папки старых библиотек (или любая папка) → задачи; файлы, которые ещё раздаются, пропускаются; после проверки оригинал удаляется. Новая библиотека тоже может быть источником (обработка на месте). `[tmdbid-N]` в имени папки используется для распознавания.
- Библиотеки Jellyfin создаются только по кнопке.

## Универсальность (требование: продукт для сообщества)
- Ничего не зашито под конкретный сервер: пути, адреса, языки, расписание — в мастере.
- Сделано: VAAPI Intel + AMD (проверено: Intel HD 620 (Kaby Lake), AMD RX 7700/7800), запасной вариант на процессоре, драйверы обоих в образе.
- Перед публикацией: английский интерфейс и выбор языка в мастере (языки дорожек и название «Голос громче» — от выбранного языка), NVIDIA NVENC (экспериментально — не на чем проверить), образы amd64/arm64 на GHCR, README на английском, лицензия MIT.
